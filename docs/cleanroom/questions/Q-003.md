# Q-003: what does `final`'s output 0 mean outside 0..1?

- **Spec section:** revision 1, 6.1.4 (lines 853-861), "Writing": "`final` writes to the screen; its output 0 is the
  displayed colour". 5.5 (lines 818-819), "Colour encoding": no source describes sRGB-encoded render targets, and the
  spec team reads stored values as "plain numbers the pack controls" (OQ-39, line 1159, "Inferred, not stated"). 3.2
  (line 416): `supportsColorCorrection`, "the pack converts to the display colour space itself (`currentColorSpace`)",
  default false, tier E. 5.2 (line 678): `currentColorSpace`, int, "0 sRGB, 1 DCI-P3, 2 Display P3, 3 Rec. 2020, 4
  Adobe RGB", tier E. The spec names no range for output 0 and does not mention HDR or extended-range displays.
- **Question:** does the format say anything about values above 1 (or below 0) in `final`'s output 0: are they
  clipped, or may they mean light past the display's white on an HDR or extended-range display? Is `currentColorSpace`
  only about primaries (which of the five gamuts the display uses), or does any of its values, or
  `supportsColorCorrection = true`, also say that the pack's output 0 is encoded for, or may go past white on, such a
  display? And what does output 0 hold when `supportsColorCorrection` is false: sRGB-encoded values for an sRGB
  display?
- **What was observed:** Sunrise serves neither `supportsColorCorrection` nor `currentColorSpace` today: neither name
  appears in its code. `final` draws into the renderer's frame (`targets[0] = target(screen)`,
  `crates/sunrise-render-shaderpack/src/pack_post/construction.rs:1343-1344`; the screen format is the frame's,
  `crates/sunrise-client-render/src/gfx/shader_pack.rs:75-78`, `:224`, `:302-305`). With a `shaders/` pack active the
  frame is not the float one: the pack's frame request carries only `hdr_float`, which `picked_pack_shape` sets only
  when no pack is active (`hdr_float: !active && switch`,
  `crates/sunrise-client/src/game/interface/shader_packs.rs:167-171`, `:190`), so `frame_format`
  (`crates/sunrise-client-render/src/gfx/frame_policy.rs:13-27`) gives the swapchain's format, which is the 8-bit
  `Bgra8Unorm` or `Rgba8Unorm` wherever the surface offers one
  (`crates/sunrise-client-render/src/gfx/device.rs:234-246`), or, with HDR output and Smooth Gradients, its own
  `WIDE_FRAME`, `Rgba16Unorm` (`frame_policy.rs:22-23`, `device.rs:251`), whose doc comment says it "clips at white
  after every pass as the 8-bit frame does" (`device.rs:248-250`). On these unorm frames a value above 1 in output 0
  is stored as 1: Sunrise clips `final` at 1. No `sunrise.hdr` key exists yet: sunrise-org/sunrise#5827 plans one, of
  Sunrise's own and opt-in, for packs that write light past white; it would define nothing in the format.
