# Q-004: may a pack rely on a loader ignoring a `shaders.properties` key it doesn't know?

- **Spec section:** revision 1, 0.4 (lines 51-56), "Out of scope": mod integrations (`dh*` programs and keys, Voxy
  `voxy.json`, Colorwheel `colorwheel.properties` and others); "Packs that ship such files must still load; the extra
  files are ignored". 3.2 (lines 463-465), "Keys seen in packs but not documented": `breaksAnisotropy` and the
  mod-support keys of 0.4, pointing to OQ-24 (line 1144): "`breaksAnisotropy` and other unknown keys: ignore with a
  log line?". 3.2 (lines 372-379) says an unknown flag in `iris.features.required` refuses the pack, and one in
  `iris.features.optional` is ignored.
- **Question:** is ignoring an unknown `shaders.properties` key a rule of the format in every tier, so that a pack may
  add a key that only some loaders read (an extension key such as `sunrise.hdr`) and still load unchanged elsewhere,
  or does 0.4's "must still load" cover only the mod-integration files and keys it lists, leaving other unknown keys
  undefined? If unknown keys are ignored, is a log line for each one part of the rule (OQ-24)?
- **What was observed:** `Properties::parse` keeps every `key=value` line of the active branches, whatever its key
  (`crates/sunrise-shaders/src/properties.rs:38-117`; keys are trimmed, and only `uniform.*`, `variable.*`, `image.*`
  and `size.buffer.*` lines have macros expanded). None of its notes is about a key's name: they are for a line that
  is not `key=value` (`properties.rs:110`), a repeated key (`:133-145`), a macro expansion that stops, on its work
  budget, its depth or a call's argument count (`:96-101`; `crates/sunrise-glsl/src/macros.rs:36-44`), and directive
  errors, a bad `#define` included (`:113-115`, `:156-178`). Each consumer then looks up the names or prefixes it
  reads (`Properties::get` and `entry`, `properties.rs:119-125`; the loops over `entries` in `textures.rs:77`,
  `screens.rs:35`, `custom.rs:223`, `post.rs:886`, `:1955`, `:2006`), so a key no consumer reads loads with no note
  and changes nothing. Sunrise ignores unknown keys silently for now. No `sunrise.hdr` key exists yet:
  sunrise-org/sunrise#5827 plans opt-in keys of Sunrise's own, `sunrise.hdr` and `sunrise.hdr.tonemap`, and needs a
  loader that doesn't know them to load the pack as if they were absent.
