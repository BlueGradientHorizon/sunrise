# A sampled transient target the pass does not declare in its reads is refused

A draw or compute dispatch that samples a transient colour or depth attachment must declare `.reads(FrameTarget::Transient(id))` on a consumer pass that does not write that transient. As in vanilla's `FramePass.reads`, the graph computes the target's lifetime from declared uses. The old runner could drop a command if its undeclared target was not live when the pass ran.

An undeclared sample is now refused at submit with `PipelineDrawError::InvalidBinding` for a draw or `ComputeDispatchError::InvalidBinding` for a dispatch, even if the pass lists the transient in `.writes(...)`. The exception is a draw sampling its own transient render attachment: that returns `PipelineDrawError::TargetReadWriteHazard`. Adding the read to a pass that already writes the transient (as its attachment or in `.writes(...)`) returns `FrameGraphError::SelfDependency` before recording. Split the producer and consumer instead, and declare the read on the consumer. Refused commands record nothing. The error types and hook signatures are unchanged.
